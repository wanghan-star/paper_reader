# 翻译完整性修复

用户反馈：阅读真实 PDF 时提示「Codex 返回的译文不完整」。现有单次响应必须精确包含所有句子；少一句就丢弃整批结果。

选择在本地 Codex 网关恢复缺失结果，前端接收逐句进度。单纯放宽数量检查会遗漏内容；只重试整批会重复已完成工作。恢复策略只接受可确定原始编号的有效译文，对缺失编号进行较小批次补译。

- 前后端默认每批最多 12 句、3500 字符；单独较长句子仍允许处理。
- 有效 JSON 和截断 JSON 中已经完成的对象都可以逐条校验。空译文、未知编号和重复编号不予采用。
- 原始编号在请求和进度中始终保持一致。补译只发送缺失句子，每轮减少批次大小，每句最多尝试三次；取消立即停止下一次请求。
- 任务进度携带累计有效译文、完成句数、总数和补译状态。失败状态也保留进度，前端先应用进度再显示错误；重新翻译跳过已有译文。
- 登录、额度和网络错误仍明确反馈，不冒充完成，也不无限重试。

验证：真实 Codex 翻译带公式和非连续编号的段落；自动测试覆盖漏译、截断、编号歧义、重试上限和取消；浏览器模拟少返回一行，检查进度、保留和继续补译。
